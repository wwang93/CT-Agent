# 教育心理学 V1.3：公开登录入口、教师审核保护与课堂 AI 限流

## 版本范围

分支：`feature/educational-psychology-v1`。面向约 100 人的一门课程，安排五次教学干预。前两次任务完整备齐，后三次待选讲义；内容备齐不等于已经发布或开放课堂。

| 页面 | 用途 | 条件 |
| --- | --- | --- |
| `/` | 五次干预导航、前两次任务与折叠课程地图 | 无课程登录要求 |
| `/preview?unit=6` 或 `10` | 四阶段固定脚手架预览 | 不保存输入，不调用 AI |
| `/student` | 正式学习、回看、自愿研究选择 | 教师发放的学习 ID + 访问码；课堂开关开启 |
| `/instructor` | 学习 ID 创建/重置、审核发布、教学观察与反馈 | 管理员赋予的教师角色 |
| `/research` | 授权子集汇总与 JSON 导出 | 独立研究者角色及有效同意 |
| `/auth` | 学生/教师 ID + 访问码；兼容已有邮箱账号 | 独立 Supabase Auth 项目 |

托管平台访问权限与课程账号是两层不同的权限。本轮用户已授权公开登录入口；课程记录、教师管理和研究数据仍需账号及对应权限。用户要求先准备两次任务、审核后再开启课堂，因此课堂开关仍为 `false`；公开入口不等于正式任务已经可开始。

## 免邮箱的固定学习身份

学生无需提供邮箱或接收验证码。教师在工作台创建 `L-001` 等固定学习 ID；默认访问码由安全随机数一次生成，之后固定使用。教师也可逐人手动指定 12—128 位字母、数字、短横线或下划线组成的访问码，不用学号、ID 或全班共用密码。ID 大小写统一，不允许姓名、邮箱、手机号。

教师可在表单填入最多 100 个 ID，逐个创建并显示进度；已有可用 ID 跳过，不覆盖其访问码。中断/保存失败的身份保持不可用，可重新执行相同 ID 恢复。访问码只在创建/重置的响应及当前教师页面内存中存在，教学数据库只存 ID 到 Auth UUID 的映射、状态与凭证版本。务必下载本次私密 CSV、逐人发放，不把 CSV 作为研究材料或全班共享；丢失不能查询原码，只能重置。

后台继续使用 Supabase 密码验证和原有会话机制，不自建 JWT、不信任客户端提交的用户 UUID。每个学习 ID 有一个不可投递的内部 `.invalid` 邮箱别名，仅作为 Auth 技术标识；它不是学生真实邮箱，不发验证邮件。账号由教师授权的服务端创建并确认，公开邮箱注册的验证配置不变。访问码哈希交给 Supabase Auth，代码和教学记录不存明文访问码。

教师创建学习 ID 时完成课程成员登记，不需要再填共享邀请码；旧邮箱学生账号仍保留邀请码入课流程。课堂关闭时可以登录/查看自己的历史、撤回研究同意，但不能开始或提交正式学习。

教师也可免邮箱：管理员在受信任的本地配置流程中创建 `T-001`，设置不可由学生编辑的角色元数据及数据库教师权限。公开 API 只允许教师创建学生，忽略客户端角色字段，`T-` 命名空间保留给管理员；不能通过学生管理入口重置教师访问码。首个教师初始化函数仅服务端可用，**没有 HTTP 路由**，且只在独立库无教师时运行，不自动覆盖已有权限。教师访问码由管理员恢复，原有邮箱教师与独立研究者登录仍兼容。

同一设备沿用有效登录会话；换设备重新输入同一 ID 和访问码，记录继续关联原 Auth UUID。重置访问码不改变 UUID、课程成员、同意或会话记录；服务端检查 JWT 中的凭证版本，旧版本访问令牌不能访问应用。密码变更的刷新会话行为依赖 Supabase Auth，部署联调需验证旧刷新令牌失效。

登录端点只接受小型同源 JSON 请求，返回 `private, no-store`；服务端持久化 CAS 限流，每个已配置 ID 每五分钟最多 10 次尝试；课程分 32 个固定限流分片，各 20 次，总预算最多 640 次，分片本身也有上限。不存在的随机 ID 不创建永久的逐 ID 限流记录。遇到限流返回 `429` 和 `Retry-After`，登录页保留 ID/访问码并显示倒计时，不自动重发。Supabase 另有限流，密码登录代理与刷新仍可能受共享出口或突发请求配额影响；不信任客户端 IP 请求头，也不伪造 IP 绕过其限流。免邮箱消除了验证邮件依赖，不等于已经通过 100 人同时登录/AI 请求压测。

教学端显示老师发放的学习 ID；研究端继续使用原哈希假名，不导出发放名单 ID、访问码或 Auth UUID，并检查当前有效研究同意。假名化不等于匿名化，也不能保证访问码持有人就是原学生。

## 干预与讲义

| 干预编号 | 教学周（默认，可由教师调整） | 课程单元 | 内容 |
| --- | --- | --- | --- |
| 1 | 7 | 6 | Week 7：注意、认知负荷、意义编码、提取练习；重建学习经历并用证据解释 |
| 2 | 10 | 10 | Week 10：初始判断、批判性评价、创造性生成、选择修订、迁移 |
| 3–5 | 待确定 | 待确定 | 等待教师选定讲义，不可开始任务 |

单元 9 的旧样板源码和所有历史会话保留，但不允许新开或发布该旧样板。旧会话没有干预编号时保持未知，不自动赋值为本轮干预。本轮已在独立课程库保存前两次未审核草稿，默认教学周分别为 7、10；没有代替教师勾选审核或发布。`saveDraft` 无论客户端如何提交审核字段，都强制保存为未发布、无审核人/时间。若已有教师配置，准备流程不覆盖它。旧单元 6 配置不自动成为干预 1。

每次学习为独立初答 → 解释与修订（教师三层提示、按需 AI 追问）→ 独立迁移 → 反思。AI 只在修订阶段开放；迁移和反思题不进入 AI 上下文。教师补充说明仍会进入上下文，应避免提前写入迁移题或测试答案。阶段控制不是受监考考试或防止学生自行使用其他工具的保证。

## 统一 AI Provider

默认直接使用 DeepSeek 官方接口：`EDU_AI_PROVIDER=deepseek`、`DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL=deepseek-flash`。固定地址 `https://api.deepseek.com`；关闭 thinking，使用 DeepSeek 的 `max_tokens`，不把 OpenAI 专用参数直接复制过去。

管理员可显式选择 `EDU_AI_PROVIDER=openai` 并配置 `OPENAI_API_KEY` / `EDU_OPENAI_MODEL`。没有自动回退；备用不等于研究对照组。新会话保存供应商、请求模型、思考模式和课程版本，运行配置变化不改写已有会话。供应商模型别名仍可能更新，因此每次成功调用另存其返回模型、时间、提示词版本、输入/输出 token 和耗时。

API Key 仅在服务端读取。源码和 `.env.example` 只记录变量名；`.env.local` 已忽略。不要使用 `NEXT_PUBLIC_DEEPSEEK_API_KEY`，不要复制原生产数据或公开供应商密钥。学生不需要 AI 平台账号。

全班共享 AI 并发与每日请求预算，记录在独立数据库中，由比较交换控制，跨 Worker 实例生效。默认 `EDU_AI_MAX_CONCURRENT=20`（最大 32）、`EDU_AI_DAILY_REQUEST_LIMIT=1000`（最大 10000），无效配置拒绝请求而非关闭保护。租约 90 秒，到期可恢复；迟到的旧请求不能释放新请求的租约。有限次数探测可能在部分槽位空闲时也返回忙碌，优先保护数据库负载，不保证每次都充分利用全部槽位。

并发占满时在调用模型前返回 `429` 和 15 秒等待建议，不写入会话答疑/失败轮数。学生页面保留问题和倒计时，不自动重发；固定教师提示仍可使用。每日预算按北京时间 00:00 重置，包含失败及保守预留，不是消费金额上限或供应商计费承诺。教师工作台显示限制和当日预留计数；供应商余额、成本告警仍须在供应商控制台管理。

## 数据与权限

沿用 Postgres `course_templates` 表作为首版原子记录容器，限定 `course_id=0833032`、`week_number=0`、`assignment_id=edu:*`。这里的 `week_number=0` 是存储命名空间，教师设置的真实教学周保存在任务配置中，单元号不强行等同于教学周。

- `edu:config:{unit}`：未审核草稿或已发布任务版本；`edu:settings`：邀请码哈希、研究开关、研究告知及教学记录说明版本。
- `edu:teaching-ack:{user}`：学生已阅读的教学记录说明版本与时间，独立于研究同意。
- `edu:member:{user}`：入课；`edu:consent:{user}`：当前研究选择。
- `edu:learning-account:{ID}`、`edu:learning-user:{UUID}`：学生身份映射、创建/重置状态与凭证版本；不存访问码。
- `edu:login-limit:*`：课程及学习 ID 的持久化登录限流计数，不存访问码或聊天内容。
- `edu:ai-slot:{n}`、`edu:ai-budget:current`：全班 AI 租约及北京时间当日请求预留计数，不存问题或密钥。
- `edu:session:{id}`：任务快照、初答/修订/迁移/反思、提示、AI 往返与教师反馈。
- 每次写入用 `template_version` 比较交换；一个会话的可见状态和交互事件一起提交，避免记录与进度分别成功。
- AI 请求先加 90 秒会话锁；模型超时 30 秒、不自动重试，失败事件与解锁原子保存，不返回假成功。每会话最多 8 次成功答疑、20 次成功/失败请求合计，三个固定提示；每任务版本最多 3 次已完成尝试。保存失败或调用结果不确定时仍可能产生供应商费用，重试前应检查记录。
- AI 只接收当前任务相关材料、最近对话和问题；发送前遮蔽邮箱与部分中国手机号，仍不保证匿名。内部推理内容不保存，不将对话日志等同于学生真实认知。
- 新注册账号只能是学生，不信任可编辑的注册元数据。教师可看教学记录，研究者不可直接打开任意完整会话；研究读取单独检查当前有效同意。
- 退出研究后，未来的研究读取与导出排除该学生历史记录。已导出的文件需要研究负责人按方案处理，系统无法从他人的设备召回。
- 假名化学习编号不是匿名化。自由文本仍可能识别个人，邮箱和部分电话遮蔽不构成完整匿名化；导出/发表前必须人工审查。

教师须填写实际联系渠道、保存期限及到期处理安排，并核实教学记录说明后保存；系统不会代替教师作出制度或合规判断，也不会按填写的文本自动删除数据。说明涵盖教学目的、访问者、模型服务商及当前独立 Supabase 新加坡基础设施。学生开始或继续写入正式任务前须确认已阅读当前版本；说明修改使旧阅读确认失效，回看自己的历史及退出研究仍可进行。这是教学告知阅读确认，不是研究同意或法律合规证明。

本版查询每页 200、最多 2400 条，达到上限会显式提示不完整。适合小规模试点，不是多课程分析仓库；扩大到全课程/多学期前拆分专用任务、会话和事件表，加入增量分页、审计、保留期限执行与聚合查询。

## 课堂启用清单（上线前必做）

1. 创建**独立** Supabase 项目；按顺序在其 SQL 控制台执行 `supabase/schema.sql` 和 `supabase/education-v1-security.sql`。不要在原生产库上盲目执行。
2. 验证三个表已开启 RLS；`anon` / `authenticated` 无直接读写权限，前端公钥不能读取会话或改写 `profiles`。仅服务端 service-role key 可操作。
3. 在托管平台的安全环境变量设置中配置 `.env.example` 对应值。公开 Auth URL/公钥和服务端 URL 必须指向同一个新项目；service-role key 和模型 key 只能放服务端秘密，不提交 Git，也不要发在聊天中。
4. 在 Supabase Auth 配置本站的 `/auth/callback` 与 `/auth/reset-password` 重定向，检查教师/旧邮箱账号的邮件配置。学生 ID 登录无需邮件、无需开启匿名登录或关闭公开邮箱验证。先验证 ID 登录、换设备接续与教师重置。
5. 由管理员核验教师身份，受控创建教师 ID（如 `T-001`），或为已有邮箱账号分配 `instructor`。初始访问码只保存在已忽略的 `teacher-access.local.txt`、权限 `0600`，不提交源码。研究者单独分配 `researcher`；普通学生不能自行申请提升。
6. 教师审核两次讲义干预的案例、四阶段问题、提示、来源与标准，再发布新版本、确认教学周。创建固定学习 ID、下载并逐人发放私密访问码；共享邀请码仅用于已有邮箱学生。
7. 在工作台完成“开课前的教学记录说明”：填写真实联系渠道、保存期限及到期处理安排，核实学校的数据使用要求并确认保存。研究不开启时不向研究者提供数据；若开展研究，完成所需审查并发布完整告知，学生自愿参与且不影响成绩。
8. 完成真实双学生账号越权测试、任务保存/刷新/并发测试、AI 失败测试、研究退出测试。确认无误才将 `EDU_CLASSROOM_ENABLED` 设为 `true` 并重新发布。
9. 先邀请 5–10 人用真实校园网络试用，再做接近课堂高峰的并发与模型成本测算。共享并发/请求配额已实现，但本版未声称通过 100 个独立学生同时登录或 100 次真实模型请求；中国大陆校园可达性尚未实测。
10. 公开外层入口遵循用户本轮授权；课程 API 仍拒绝匿名和越权请求。不要将访问码发到全班群，也不要公开发放 CSV。

课堂开关关闭时，已有学生仍可读历史记录、撤回研究同意；不能新入课或提交学习阶段。

## 部署方式

保留标准 Next 部署能力：Vercel 可对这个 Git 分支单独部署预览，**不能把原项目生产分支切换到此分支，也不能复制原库数据来测试**。

本版另外提供 Sites 的独立 Worker 构建，沿用现有 Next 架构，通过 OpenNext 适配：

```bash
npm ci
npm run build:sites
```

输出为 `dist/server/index.js` 和 `dist/client`，`.openai/hosting.json` 只存站点 ID，不存任何密钥。打包脚本清空 OpenNext 自动生成的 `.env*` 回退值并检查产物中的已知密钥；服务端配置只由 Sites 运行时注入。`wrangler` 仅执行 `--dry-run` 本地打包，不向 Cloudflare 账户发布；正式发布由 Sites 的保存版本/私有部署操作完成。GitHub 分支与 Sites 源码仓库应指向同一提交。

Next 固定为 16.3.8。锁文件升级相关安全补丁（包括 proxy-addr、brace-expansion、sharp、source-map-js、undici 和 baseline-browser-mapping）；本轮 `npm audit` 报告 0 项已知漏洞。这不构成无漏洞或合规保证，仍须持续维护依赖和权限。

无 Auth/数据库/模型配置时：首页和预览可访问；正式页面显示未配置提示，AI 不可用，不制造模拟对话、假学生、假图表或假数据保存。只有上述清单完成后才能称为可投入真实课堂的版本。

## 本轮技术验收与边界

- 15 组自动化测试通过，覆盖角色、访问码重置后所有权、旧令牌拒绝、四阶段顺序、AI 错误与幂等、草稿强制未审核、教学说明变更保护、研究同意撤回、CAS 并发及预算。
- 100 个同时发起的模拟 AI 准入请求未超过 20 个共享槽位；忙碌请求不调用模型、不占答疑轮数。此项使用数据库替身，不是供应商真实吞吐测试。
- 本地应用连接真实独立课程库，用两个临时 QA 身份验证匿名/越权请求拒绝、直接数据库访问拒绝、四阶段合成记录保存回读和跨学生隔离。课堂和研究始终保持关闭；合成记录由受控管理员种入用于技术验收，不代表学生正式完成任务。
- 两次真实 DeepSeek 请求分别验证 Week 7/10 中文支持；返回模型均为 `deepseek-flash`，总 token 分别为 999、1012。不发送真实学生隐私，不把模型回复视为教学效果证据。
- 两个临时身份下的 100 个并发课程读取请求全部成功（本地 Node 服务约 5.4 秒）；不是 100 个独立身份登录，也不等于生产 Worker 容量保证。临时身份和合成记录已定点清理，不混入教学统计。
- 可复用 `scripts/verify-education-live.ts` 进行受控验收。默认不调用模型；`--with-ai` 仅发两次合成问题，`--prepare-drafts` 仅在配置不存在时保存未审核草稿；不改课堂、研究或教学告知开关。凭证不输出，不保存在测试报告中。

教师下一步：用 `T-001` 登录 → 填写并确认教学记录说明 → 分别审核、发布两次草稿 → 创建并私密发放学生 ID/访问码 → 告知管理员“审核完成，开启课堂”。不要在最后确认前开启课堂。

## 可继续迭代

- 根据选定讲义补齐剩余三次干预，不默认将剩余 13 单元都改为 AI 任务。
- 小组讨论与课堂提问收集、人工编码量规、教师回复提醒。
- 按学期的保留期限与删除工作流、研究导出审计、匿名化人工复核。
- 使用知识材料检索与来源核验扩展概念支持；在明确样本和方案后评估脚手架的效果，不从日志直接推断认知增益。
